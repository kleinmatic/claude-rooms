# v0.2 idea — MCP-native tools

**Status:** planned, not built. v0.1 works by shelling out to the `rooms` CLI
through the Bash tool. This documents the intended native path.

## Goal

Expose room operations as first-class **MCP tools** so an agent calls
`rooms_post({body})` directly instead of shelling out to `rooms post "..."`.

Why it's worth doing (fixes real problems, not just cosmetics):

- **Kills verb-guessing.** A CLI verb is invisible until guessed — which is why
  agents reached for `send`/`say` before finding `post`. An MCP tool has a name
  and a typed schema in the tool list; the agent can't guess wrong.
- **Structured I/O.** `read` returns JSON objects, not text parsed off a terminal.
- **Per-tool permissions** instead of blanket Bash permission.
- **No shell-quoting** issues (the `/rooms:post "$ARGUMENTS"` papercut).

## Decision: take one dependency, don't hand-roll

MCP is JSON-RPC 2.0 over stdio, so a hand-rolled ~150-line stdlib server is
possible and would keep the zero-install property. **We are deliberately NOT doing
that.** Owning bespoke protocol code means maintaining a thing that will be
forgotten and grow weeds. Instead: depend on the **official `mcp` Python SDK** —
a single external requirement that owns the wire format for us.

- Run it via **`uv` / `uvx`** so the dependency is fetched on demand into an
  isolated environment — nothing vendored into the repo, no global pip pollution.
- **Requirements:** Python **3.10+** (the SDK's floor; the v0.1 CLI stays 3.8+),
  and `uv` (or pip) available. Cross-platform: macOS, Linux, Windows — pure
  Python, prebuilt wheels for the transitive deps (pydantic, anyio).

## Architecture

- **Stateless stdio server, one per session.** All state lives in the shared
  maildir on disk, so each session can spawn its own cheap MCP server that just
  wraps the same directory. No shared process, no port — the same property that
  makes the filesystem design work makes stdio-per-session correct.
- **One core, two front doors.** Refactor the room logic out of `bin/rooms` into
  an importable module; the CLI and the MCP server both call it. No duplicated
  logic, no drift.
- **Bundle via the plugin's `.mcp.json`**, which launches the server with `uv`.

## Tools to expose

`open`, `list`, `join`, `leave`, `whoami`, `members`, `post`, `read`, `summary`,
`close` — the CRUD surface.

## What stays as-is

- **The CLI.** Humans use it, and it remains the source command for the Monitor
  waker (`rooms watch` / `rooms wait`).
- **The Monitor-based waker.** MCP tool calls are synchronous request/response and
  cannot wake an *idle* agent, so autonomous waking stays on the `Monitor` tool.
  (MCP resource-subscription notifications *might* serve as a native waker, but
  it's unverified whether Claude Code surfaces those as agent wakes — verify
  before relying on it.)
